L0.1 · MÉTIERS DE LA DATA

Qui fait quoi dans une équipe data ?

Une équipe transforme une question métier en décision. Plusieurs métiers collaborent, avec des responsabilités différentes.

Analyste de données

Explore les données, répond aux questions et partage des indicateurs.

Data engineer

Construit et entretient les flux qui rendent les données accessibles.

Data scientist

Utilise des méthodes statistiques et des modèles pour étudier des phénomènes.

ML engineer

Met en production et surveille des modèles de machine learning.

AI engineer

Conçoit des applications qui s'appuient sur des modèles d'intelligence artificielle.

Gouvernance des données

Définit des règles de qualité, d'accès, de documentation et de protection.

Ces rôles se recouvrent parfois. Dans ce parcours, tu apprendras d'abord à poser une question claire, vérifier les données et expliquer tes conclusions.

L0.2 · TON POSTE DE TRAVAIL

Installer et vérifier les outils

Tu as besoin d'un éditeur, de Python et de Git sur ton ordinateur. Le site du cours ne nécessite pas ces installations pour consulter les leçons.

  1. Installe Visual Studio Code, ton éditeur de fichiers et de code.
  2. Installe Python 3. Sous Windows, coche « Add Python to PATH » si l'option apparaît.
  3. Installe Git, qui conserve l'historique de ton travail.
  4. Ouvre un nouveau terminal et vérifie les versions avec les commandes ci-dessous.
# Windows — essaie py si python n'est pas reconnu
py --version
git --version

# macOS ou Linux
python3 --version
git --version

Tu dois voir un numéro de version pour Python et Git. Si la commande n'est pas reconnue, ferme et rouvre le terminal après l'installation.

N'installe pas de paquet Python pour suivre les exercices de ce module : ils s'exécutent dans le navigateur. Les outils locaux serviront aux projets suivants.

L0.3 · SIX COMMANDES GIT

Garder une histoire claire de ton travail

Git est un outil de versionnement : il garde des points de repère de tes fichiers. GitHub héberge une copie distante que tu peux partager.

  1. git clone URLCopie un dépôt distant sur ton ordinateur.
  2. git statusMontre les fichiers modifiés, préparés ou non suivis.
  3. git add README.mdPrépare les changements sélectionnés pour le prochain commit.
  4. git commit -m "Décris le changement"Enregistre un instantané local des changements préparés.
  5. git pushEnvoie tes commits vers le dépôt distant.
  6. git pullRécupère et intègre les changements du dépôt distant.

Le cycle habituel est status, add, commit, puis push. Le commit reste local tant que tu ne le pousses pas.

À quoi sert le fichier .gitignore ?

Il indique à Git quels fichiers locaux ne doivent pas être suivis, par exemple un environnement virtuel ou des paramètres privés. Vérifie toujours le contenu avant de publier : .gitignore ne retire pas un secret déjà commité.

L0.4 · ORGANISER UN PROJET

Ranger tes fichiers pour les retrouver

Un dépôt simple sépare les données, les analyses et le code réutilisable. Choisis des noms explicites et explique le projet dans README.md.

data-portfolio/
├── README.md
├── data/
├── notebooks/
└── src/
  • data/ contient les fichiers de données autorisés.
  • notebooks/ contient les explorations et analyses.
  • src/ contient le code Python réutilisable.
  • README.md présente le but, les étapes et les limites du projet.

Ne publie jamais de mot de passe, clé d'API, donnée personnelle ou fichier dont tu n'as pas le droit de partage.

L0.5 · CSV, JSON ET GRAIN

Demander : « une ligne représente quoi ? »

Le grain d'une table est l'objet représenté par une ligne. Le définir évite de confondre le nombre de commandes avec le nombre de clients.

CSV

Des lignes et colonnes en texte, adaptées aux tableaux simples. Le format ne conserve pas les formules ou la mise en forme d'un tableur.

JSON

Des objets et des listes structurés, souvent utilisés pour les réponses d'API. Les objets peuvent être imbriqués.

Exemple : si une table contient une ligne par article commandé, une commande avec trois articles produit trois lignes. Pour compter les commandes, compte les identifiants de commande distincts.

order_id,product,quantity
O-101,shield,1
O-101,potion,2

Dans cet extrait, le grain est l'article commandé. Les deux lignes peuvent appartenir à la même commande.

L0.6 · PREMIER APPEL D'API

Lire une réponse du Compendium

Une API expose des données par des requêtes. Une requête GET demande une ressource ; la réponse contient un statut HTTP et, souvent, un document JSON.

  1. Construis l'adresse d'une ressource documentée.
  2. Envoie la requête GET et vérifie son statut.
  3. Lis les clés du JSON au lieu de supposer sa structure.
  4. Traite les valeurs absentes et les erreurs réseau.
https://api.hyrule-compendium.com/v3/compendium/entry/white-maned_lynel

Dans l'exercice, get_json(url) renvoie le JSON de la réponse. Le cours tente l'API en ligne, puis utilise le miroir local si le service est indisponible.

Un statut réussi ne garantit pas que la liste renvoyée contient des éléments. Vérifie le contenu et le contexte de la réponse.

E0.1 · 10 XP

Interroger le Compendium

Récupère une entrée, vérifie sa catégorie et calcule le nombre de butins.

Indice 1

Une URL d'API se passe à get_json et sa réponse est un objet Python.

Indice 2

La ressource renvoie les données dans une clé nommée data. Vérifie aussi la catégorie.

Indice 3

Une liste absente peut être traitée comme une liste vide avec entry.get("drops") or [].

Solution commentée
response_data = await get_json(url)
entry = response_data["data"]
drops = entry.get("drops") or []
result = f"{entry['category']}|{len(drops)}"
E0.2 · 15 XP

Compter les catégories

Lis le snapshot local et compte combien d'entrées appartiennent à chaque catégorie.

Indice 1

Utilise le module standard json et ouvre le chemin fourni dans le code de départ.

Indice 2

Parcours snapshot["entries"], puis lis la clé category de chaque entrée.

Indice 3

Un dictionnaire peut stocker un compteur par catégorie avec counts.get(category, 0) + 1.

Solution commentée
counts = {}
for entry in snapshot["entries"]:
    category = entry["category"]
    counts[category] = counts.get(category, 0) + 1
result = sum(counts.values())
E0.3 · 15 XP

Comparer les lieux des monstres

Classe les monstres par nombre de lieux connus. Traite les valeurs nulles et départage les égalités par nom.

Indice 1

Filtre les entrées dont la catégorie est monsters.

Indice 2

Utilise entry.get("common_locations") or [] avant de compter.

Indice 3

Pour un tri décroissant par nombre puis alphabétique, la clé peut être (-nombre, nom).

Solution commentée
ranked = sorted(
    monsters,
    key=lambda entry: (-len(entry.get("common_locations") or []), entry["name"]),
)
top_five = [entry["name"] for entry in ranked[:5]]
result = json.dumps(top_five, ensure_ascii=False)

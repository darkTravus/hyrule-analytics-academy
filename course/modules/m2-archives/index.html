L2.1 · MODÈLE RELATIONNEL

Une table, une entité, un grain

Une base relationnelle répartit l'information entre des tables reliées par des clés. Dans players, une ligne représente un joueur; dans sessions, une ligne représente une session. Cette différence de grain est essentielle avant de compter ou de joindre.

Clé primaire (PK)

Identifie une ligne sans ambiguïté. players.player_id est unique; order_lines a une clé composée de order_id et line_no.

Clé étrangère (FK)

Pointe vers une clé d'une autre table. sessions.player_id rattache chaque session à son joueur.

Cardinalité

Un joueur peut avoir zéro ou plusieurs sessions (1 vers 0..n). Une commande possède une ou plusieurs lignes.

Une relation plusieurs-à-plusieurs passe par une table d'association : joueurs et expériences sont reliés via experiment_assignments.

L2.2 · SÉLECTION ET FILTRES

Demander juste ce qu'il faut

SELECT choisit les colonnes, FROM la table de départ, WHERE filtre les lignes et ORDER BY les trie. LIMIT réduit le nombre de lignes affichées.

SELECT player_id, country, platform
FROM players
WHERE country = 'FR' AND is_premium = 1
ORDER BY signup_date DESC, player_id
LIMIT 20;

Une chaîne doit être entourée d'apostrophes. Utilise une seconde colonne de tri pour rendre les ex-aequo stables. Pour tester une absence, écris IS NULL, jamais = NULL.

L2.3 · AGRÉGATIONS

Former et filtrer des groupes

COUNT, SUM, AVG, MIN et MAX résument les lignes. GROUP BY définit les groupes; HAVING filtre leurs résultats.

SELECT platform, COUNT(*) AS players
FROM players
GROUP BY platform
HAVING COUNT(*) > 100
ORDER BY players DESC;

COUNT(*) compte les lignes; COUNT(colonne) ignore les valeurs NULL. Une colonne sélectionnée qui n'est pas agrégée doit généralement figurer dans GROUP BY.

L2.4 · JOINTURES

Relier sans perdre le grain

INNER JOIN ne garde que les lignes appariées. LEFT JOIN conserve toutes les lignes de gauche et remplit par NULL quand il n'existe pas de correspondance.

SELECT p.platform, COUNT(DISTINCT p.player_id) AS players,
       COUNT(s.session_id) AS sessions
FROM players p
LEFT JOIN sessions s ON s.player_id = p.player_id
GROUP BY p.platform;

Les sessions ont plusieurs lignes par joueur : COUNT(*) compterait des sessions, pas des joueurs. Une condition sur la table de droite placée dans WHERE peut retirer les lignes NULL et annuler l'effet du LEFT JOIN.

L2.5 · CASE, DATES ET CTE

Découper le raisonnement

CASE WHEN construit une catégorie. Dans SQLite, strftime extrait des éléments de date; julianday permet de calculer un écart en jours. Une sous-requête ou un CTE WITH nomme un résultat intermédiaire.

WITH monthly AS (
  SELECT strftime('%Y-%m', start_ts) AS month, COUNT(*) AS sessions
  FROM sessions
  GROUP BY month
)
SELECT month, sessions
FROM monthly
WHERE sessions > 100
ORDER BY month;

Dans les dates ISO de ce cours, comparer deux chaînes au format AAAA-MM-JJ est également sûr pour un ordre chronologique.

L2.6 · FONCTIONS DE FENÊTRE

Comparer sans réduire les lignes

Les fonctions de fenêtre calculent sur un voisinage tout en conservant chaque ligne. ROW_NUMBER attribue un rang unique; RANK partage les ex-aequo; LAG lit une ligne précédente.

SELECT player_id, start_ts,
       LAG(start_ts) OVER (
         PARTITION BY player_id ORDER BY start_ts
       ) AS previous_session
FROM sessions;

Pour un cumul, utilise SUM(mesure) OVER (ORDER BY date). Pour le top 3 de chaque catégorie, ajoute PARTITION BY catégorie, puis filtre le rang dans une requête externe.

L2.7 · COHORTES ET RÉTENTION

Suivre les joueurs dans le temps

Une cohorte regroupe des personnes selon un événement de départ, par exemple la semaine d'inscription. La rétention est la part de cette cohorte qui revient dans une fenêtre définie.

  1. Définis le jour de départ et la taille de chaque cohorte.
  2. Relie les sessions au joueur et calcule un indicateur 0/1 par personne.
  3. Agrège ces indicateurs pour obtenir un taux cohérent.

Précise si J7 signifie « le jour exact J7 » ou « au moins une fois dans les sept premiers jours ». Ces définitions ne donnent pas la même mesure.

L2.8 · PIÈGES À ÉVITER

NULL, fan-out et division entière

NULL signifie valeur inconnue ou absente; il ne se compare pas avec =. Un fan-out survient quand deux tables de faits à plusieurs lignes par entité sont jointes ensemble : chacune multiplie les lignes de l'autre.

  • Vérifie le grain avant chaque jointure et mesure le nombre de lignes obtenu.
  • Agrège séparément les faits avant de les rapprocher si nécessaire.
  • En SQLite, 1.0 * numerateur / denominateur force une division réelle.
  • Sur un LEFT JOIN, COUNT(*) compte la ligne conservée; COUNT(clé_droite) ignore les absences.

L2.9 · PERFORMANCE

Lire un plan et comprendre les index

Un index est une structure auxiliaire qui peut accélérer une recherche ou une jointure sur certaines colonnes. Il occupe de l'espace et rend les écritures plus coûteuses; il n'améliore pas tous les plans.

Utilise EXPLAIN QUERY PLAN SELECT ... dans un outil SQLite de bureau pour observer un balayage ou l'usage d'un index. Le runner pédagogique autorise volontairement seulement les requêtes de lecture; il affiche le plan pour comprendre la requête exécutée.

L'ordre logique à garder en tête est FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT.
